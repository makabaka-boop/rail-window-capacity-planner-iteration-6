# 夜间铁路检修窗口排程

在有限的夜间检修窗口内，从一批候选作业中选出**总收益精确最大**的组合，
保证任意时段同时进行的作业数不超过作业队容量（`capacity`），并满足计划员
设定的**必选 / 排除**约束与可选的**容量日历**（部分时段下调有效容量）。
调度员还可把一次已通知作业队的成功结果**采纳为不可变参考方案**：产能
日历或约束改变后重新求解时，在**总收益严格相同的最优方案之间**尽量少
改动已通知的作业成员。

纯前端应用：**TypeScript + React + Vite**，全部计算在浏览器内完成
（求解运行在 Web Worker 中），**不调用任何在线服务、不上传数据、不附带
分析/埋点/字体/CDN 资源**。

## 数据边界（重要）

- **所有数据仅存在于本机**：导入的 JSON 只在当前浏览器页面的内存中处理；
  为了刷新后恢复工作区，界面状态（作业、约束）与最近一次成功结果会写入
  浏览器的 `localStorage`，不会离开本机。清除站点数据即可删除。
- 应用不会发起任何网络请求；静态构建产物可在完全离线环境（或
  `docker compose` 的 nginx 镜像）中运行。
- 下载的结果 JSON 由浏览器本地生成。
- **数据身份与恢复**：每次成功导入都会分配一个数据身份 `dataId`，
  工作区与求解快照仅凭 `dataId` + `version` 配对——新导入的批次同样从
  `version=1` 起步，**版本号相同但身份不同的旧结果绝不会在新工作区上
  展示或下载**。浏览器只成功写入两份记录中的一份（单键写入/中途崩溃）时，
  孤儿快照直接丢弃；存储中的日历越界/重叠、作业状态非法、结果结构不完整
  或 `selectedIds` 指向不存在作业的记录会被整体拒绝，不渲染也不导出。
  旧版本地数据（无身份字段、缺省日历、旧下载结构）在内容核对通过时
  自动补登身份并迁移。**已采纳的参考方案同样只凭 `dataId` 绑定**：
  独立存储于第三把本地键中，导入新数据或恢复到身份不配套（含旧格式
  无 `dataId`）的本地记录时绝不作用于当前工作区——异身份记录直接丢弃，
  不会被误用为 tiebreak 输入。
- **数据规模契约**：

  | 字段 | 约束 |
  | --- | --- |
  | `capacity` | 整数，`1 ≤ capacity ≤ 8` |
  | `jobs` 数量 | `1 ≤ n ≤ 50000` |
  | `id` | 唯一、非空字符串（JSON 数字会规范化为字符串） |
  | `start` / `end` | 整数，`0 ≤ start < end ≤ 1_000_000_000` |
  | `benefit` | 整数，`1 ≤ benefit ≤ 1_000_000_000` |
  | `capacityCalendar[]`（可选） | 每项 `{start,end,available}`，见下 |

- **容量日历**（可选字段 `capacityCalendar`）：在指定时段把有效容量下调。
  - 区间同样为**左闭右开**，端点为整数，范围**限于最早作业开始至最晚
    作业结束**；各片段**互不重叠但允许端点相接**。
  - `available` 为 `0..capacity-1` 的整数（取到 `capacity` 的限制无意义，
    应直接省略该片段）；`available=0` 表示该时段完全封闭。
  - **省略该字段或给空数组 = 全程 `capacity`**（旧 JSON 行为不变）。

- 区间语义为**左闭右开** `[start, end)`；两个作业端点相接
  （`end == 下一个 start`）**不算重叠**，可由同一作业队先后承担。
- 程序不做任何“占位计算”：求解结果是模型的精确最优解，不是近似/演示数据；
  无数据时界面为空仓库状态，不生成虚构作业。

## 导入 JSON 格式

```json
{
  "capacity": 2,
  "jobs": [
    { "id": "track-inspect-a", "start": 0, "end": 120, "benefit": 30 },
    { "id": "catenary-b", "start": 120, "end": 300, "benefit": 45 },
    { "id": "signal-c", "start": 60, "end": 200, "benefit": 25 }
  ],
  "capacityCalendar": [
    { "start": 60, "end": 180, "available": 1 }
  ]
}
```

非法导入会**逐项列出错误**（定位到 `jobs[i].field` 或
`capacityCalendar[i].field`），并且**整个导入被拒绝，工作区与既有结果
保持不变**。允许出现契约之外的额外字段。

## 交互与约束规则

- 每个作业可设置为 **普通 / 必选 / 排除**：
  - 必选作业必须排入；排除作业任何情况下都不入选。
  - 把作业设为必选时，若其时段内任一时间格的必选重叠数已达到该格
    **有效容量**（受容量日历影响，可能小于 `capacity`），修改会被
    **拒绝**，旧约束、旧结果均不变（界面提示原因）。
  - 取消必选后容量立即释放，可再次设置其它必选作业。
- 结果展示：**入选集合、峰值占用及最早峰值格的有效容量上限、总收益**。
- 修改约束后旧结果会标记为**已过期**；点击“重新计算”得到新的最优解。
- **计算失败不会清空最近一次成功结果**；修正约束后可直接重算。
- 页面显示的入选集合与“下载结果 JSON”中的 `selectedIds` 来自同一个数据源，
  二者严格一致；下载文件同时包含求解所用的**同一容量日历**与峰值数据。

### 只读容量占用见证（下发前逐段核对）

- 每次成功求解除峰值数字外，还生成一份只读**容量占用见证**：以**入选作业
  端点与容量日历全部端点**切分左闭右开时间轴，并把**有效容量与活动作业 ID
  集合均相同的相邻片段合并**，逐段给出 `[start,end)`、**有效容量**、
  **实际占用**、**余量**及**按导入顺序稳定排序**的作业清单。
- 结果区“容量占用见证”可展开：逐段浏览（窗口化，支持 5 万作业）、
  **按任意时刻定位片段**（半开语义：右端点属于后一片段）、在
  `available=0` 的**封闭片段**间跳转；点击片段内作业可在作业表中定位。
- **下载 JSON 与页面使用同一份见证**（顶层 `occupancyWitness` 字段）：
  见证对象生成一次，屏幕展示与下载原样引用，不存在两套计算。
  未生成见证（旧格式下载）时该字段缺省，下载结构其余部分保持不变。
- 见证**只属于生成它的 `dataId` + 工作区版本 + 入选集合**：约束变化后
  重算、异身份恢复或 Worker 迟到响应都会得到另一份结果，旧见证绝不能附到
  新方案上（下载前按三要素闸门 + 独立重建逐片段深比较双重核对）。
  过期（同身份旧版本）结果只展示指标并提示重算，**不生成见证、不可下载**；
  见证生成或核对失败同样**禁用下载**，绝不伪装成可下发的当前结果。
- 恢复时的非法记录沿用现有拒绝规则；见证不单独持久化，它永远从当前已
  配对校验通过的快照派生。

### 采纳不可变参考方案（已通知作业的最小改动）

- 点击结果区的**“采纳为参考方案”**可把当前版本的一次成功结果采纳为
  **不可变参考**（过期/计算中/空排程不可采纳）。采纳本身不重新计算：
  采纳来源就是当前严格最优解，原求解结果逐项不变。
- 此后每次求解仍**先严格最大化总收益**，并满足必选、排除及逐时段容量
  约束；**仅在总收益相同的可行方案之间**，最小化与参考方案的作业成员
  差异；差异仍并列时沿用求解器既有的确定性裁决。
- **成员身份由作业编号 `id` 与起止时刻 `start/end` 共同确定**：同一
  编号改期视为**撤下旧时刻成员 + 加入新时刻成员**（差异计 2）。
- **已从当前工作区删除的参考成员不参与可避免差异计数**：它不可能再被
  排入，结果页只将其透明列出；被设为排除/受日历所限而无法保留的成员
  属于**不可避免差异**，仍正常计入。
- 结果页相对参考方案列出**保留 / 撤下 / 新增**三类成员及可避免差异数；
  **下载 JSON 的 `reference` 区块与屏幕列表来自同一次差异计算快照**，
  二者逐项一致。未采纳参考时下载结构与旧版完全相同（无 `reference` 字段）。
- 参考方案**绑定工作区数据身份**：导入新数据立即清除内存与本地参考；
  刷新恢复时身份不配套（含旧格式、单键残留）的记录直接删除，绝不误用。

## 求解算法（精确最优）

对作业端点与容量日历端点合并做坐标压缩，在时间轴 DAG 上建立
**最小费用流**：

- 时间边 `i → i+1`：容量 `capacity`（一单位流代表一条作业队轨道）；
- 作业边 `li → ri`：容量 1，费用为负。设候选数 `n`、候选收益和
  `Bsum`，取 `K = 2n+1`、必选权重 `M = K·Bsum + 2n + 1`：
  - 普通作业费用 `-(K·benefit + ε)`；
  - 必选作业费用 `-(M + K·benefit + ε)`；
  - 已采纳参考且该作业边是**参考成员**（id+起止时刻全等）时 `ε = +1`，
    非参考成员 `ε = -1`；**未采纳或没有任何活动参考成员命中时 `ε = 0`**，
    费用结构与旧版逐位相同。
- 容量日历把时间轴切成各格有效容量 `cap_i`：在容量上升沿加入
  `S → i`（轨道上线）边、下降沿加入 `i → T`（轨道下线）边。由割守恒，
  跨越任一小格的入选作业数严格 `≤ cap_i`；无日历时退化为从时间起点
  发送 `capacity` 单位流的旧模型。

由于任意方案间的收益差乘上 `K` 后严格压过成员偏好差（`|Δε| ≤ 2n < K`），
而 `M` 又严格压过任意收益差与成员偏好差之和，费用最小化实现严格字典序：
**先最大化入选必选作业数 → 再最大化总收益 → 再最小化与参考方案的可避免
成员差异**；当必选集合逐格可行（每格必选重叠 ≤ 该格有效容量）时，最优流
必然包含全部必选作业。无参考时 `ε ≡ 0`，求解结果与旧版逐项一致。
费用/距离全程使用 **BigInt**，5 万项、单项 10 亿收益下无浮点误差
（`M` 上界约 5e13 量级，远在 BigInt 精确范围内）。

排除作业不进入网络；容量约束由时间格容量精确保证。算法只需
`O(capacity)`（至多 8，叠加极少数日历变化点）次带位势 Dijkstra 增广，
5 万作业在现代机器上秒级完成（测试门槛 3 秒）。

## 本地开发

```bash
npm install
npm run dev       # 开发服务器
npm test          # Vitest：小规模穷举、端点语义、校验、5 万项性能
npm run build     # 类型检查 + 生产构建（产物 dist/，已在 .gitignore）
npm run verify    # tsc --noEmit + vitest run（与 Docker verify 服务一致）
```

## Docker

```bash
# 托管页面（宿主机端口可用 WEB_PORT 覆盖，默认 8080）
WEB_PORT=8080 docker compose up --build web

# 一次性验收：类型检查 + 全部测试，结束后容器退出，退出码反映结果
docker compose up --build verify
```

## 测试说明

`tests/` 使用 Vitest：

- 对 1~11 项作业、容量 1~3 的 200 组随机用例做 **2^n 全子集穷举**，
  逐一核对最优总收益、峰值占用、必选/排除合规性；
- 固定用例核对左闭右开（相接不重叠）语义；
- 容量日历专项：独立穷举在「作业端点 + 日历端点」的每个时间格上
  逐格核对最优值；锁定 `capacity=2`、`[0,10) available=1` 时两项
  `[0,10)` 作业最多入选一项、两项 `[10,20)` 作业可同时入选；
  覆盖内部日历端点、必选失败隔离、旧格式结果一致；
- 必选不可行时抛出明确错误；
- 5 万作业（含带容量日历的 5 万作业、带参考成员的 5 万作业）端到端求解
  限时 3 秒并加总核对，且带参考时总收益相对无参考严格不降级。
- `referencePlan.test.ts`：两级目标专项——300 组随机小规模用例
  （1~10 项、容量 1~3、随机日历压容/必选/排除/含幽灵与改期参考成员）
  做 **2^n 全子集穷举**，按字典序 `(总收益, -可避免差异)` 核对求解结果
  必在最优集合族中；固定用例覆盖同收益 tiebreak 偏向参考、1 点收益差
  压过成员偏好、日历压容与恢复后的最优成员取舍、改期 = 撤下 + 新增、
  已删除成员不计数、必选不可行不被参考“救活”、确定性重复一致。
- `referencePersistence.test.ts`：参考方案独立第三键的身份绑定——
  同身份随会话恢复（不依赖快照）、异身份/旧格式/单键残留记录被丢弃删除、
  结构非法（缺 dataId、成员畸形、版本非正）整体拒绝、成员去重规范化、
  屏幕三类名单与下载 `reference` 区块同一快照逐项一致、
  存储抛异常（配额/安全错误）安全降级。
- `referenceWorkerRace.test.ts`：携带参考的异步旧请求迟到响应仍被
  requestId 闸门丢弃，同收益不同成员的旧结果不能覆盖新约束下的求解。
- `sessionIdentity.test.ts`：数据身份与恢复防混合——同版本异数据不配对、
  单键写入不混合恢复、畸形日历/非法状态/结构不完整或引用幽灵作业的结果
  被拒、旧合法存储（无身份/缺日历/缺 `peakCellLimit`）可恢复迁移、
  worker 消息解码失败与求解异常确定地退出“计算中”回到可重试状态。
- `occupancyWitness.test.ts`：只读容量占用见证——小时间轴逐格计数核对
  左闭右开端点相接（相接不共处同片段）、`available=0` 封闭片段、
  容量/集合相同的相邻片段合并与不合并边界、清单按导入顺序稳定排序、
  空选择与空时间轴；120 组随机用例（含日历/必选/排除）逐整数时刻独立枚举
  并校验峰值；绑定三要素（dataId/版本/入选集合）不配套、片段被篡改、
  伪造未合并片段时拒绝；生成失败（幽灵 id/重复 id/非法日历）抛
  `WitnessError` 不伪装成功；下载 JSON 与页面同一见证且旧格式（无
  `occupancyWitness`）兼容；恢复后重建一致、过期版本见证不下发、
  Worker 迟到响应旧见证不能附新方案；5 万作业见证生成/核对各在 3 秒内
  且 JSON 往返后仍合法。
